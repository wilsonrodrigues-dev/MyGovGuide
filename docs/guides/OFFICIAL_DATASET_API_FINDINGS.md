# Official dataset API investigation — 18 November 2026

This records verified official documentation and explicit unknowns. Catalog visibility, an API directory entry or a general open-data policy does not independently authorize a particular endpoint. No dataset endpoint was invented, no private beneficiary data was requested, no API provider account was created and no paid request was made.

## OGD India: access and discovery

[Official help](https://data.gov.in/help) documents API-key generation for registered users: use the portal's Login/Register flow, then the account API-key facility and the chosen resource's documented API URL. Keep any issued key only in ignored backend environment configuration (for example `DATA_GOV_IN_API_KEY`), never in frontend variables, Source Manager URLs, raw provenance or logs. No usable OGD credential/resource agreement was established in this task.

[OGD copyright/license page](https://data.gov.in/Godl) and [portal home](https://data.gov.in/) associate published datasets with GODL-India, but the current rendered license page did not expose substantive license text. Some current pages also show a sandbox/maintenance disclaimer or empty resource views. A general license statement is insufficient to certify a resource's current data or exact access method. The earlier direct host robots probe denied portal crawling; it was not bypassed. Current web-tool robots probes failed with 503/unavailable, rather than establishing changed permission.

The common API URL shape is not a verified endpoint for an arbitrary dataset. Exact resource UUID, API host/path, permitted authentication method, fields and pagination must be verified from that resource's official API specification before activating an adapter. No shared/demo key was copied from a third-party repository. US `api.data.gov` documentation is a different service and its hourly limits do **not** apply to India's `api.data.gov.in`.
