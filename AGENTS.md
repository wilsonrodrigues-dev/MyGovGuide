# MyGovGuide engineering requirements

- Latest owner amendment (21 November 2026): routine publication uses evidence-based automated validation, not mandatory human clicks; extend to all existing schemes/forms/notices/scams using targeted research, without bulk scraping. Preserve external rights, deterministic completeness, privacy and source-version integrity; never describe automated decisions as human approval. Maintain the per-record checkpoint.
- Follow `docs/FINAL_REDESIGN_ROADMAP.md` for the next phase. The pre-redesign baseline is `docs/MYGOVGUIDE_FINAL_WORKFLOW_V3.md` and `docs/OPENCODE_IMPLEMENTATION_BRIEF.md`. Retain privacy/evidence/publication safeguards in `PRODUCT_MASTER_PLAN.md` and the original SRS under `docs/requirements/`. Extend the existing JavaScript MERN project; do not rebuild it.
- Read current code, actual database state and prior receipts before editing. Preserve unrelated working-tree changes. Do not attribute all uncommitted files to the latest agent.
- Runtime data targets `mygovguide_demo_v2` through private backend configuration. Legacy `mygovguide_dev` is read-only: never seed, initialize indexes, run a worker or migrate into it. Never delete either database. Backups and all credentials stay ignored under private local storage.
- Public government visibility, successful HTTP, search results and an AI response do not establish source permissions, policy currentness, completeness or human approval. Respect myScheme restrictions and source-specific approved paths/expiry. Bound collection requests and documents.
- Keep source versions immutable. New evidence creates a new version; do not append newly researched clauses to a prior captured original. Preserve genuine owner decisions with their exact reviewed scope; do not extend a limited decision to unreviewed requirements.
- Eligibility is deterministic. Missing clauses, exclusions, unsupported boundaries or incomplete reviews must not produce a complete eligibility verdict. Keep application documents distinct from conditions.
- Reuse valid language artifacts. Gemini primary, authorized secondary and entitled Groq use the existing router and zero-paid configuration. No quota evasion. No private user documents sent to free providers. Local OCR must have installed local models, hard resource limits and truthful confidence/fallbacks.
- Admin remains Dashboard / Content / Needs Attention, with the existing collection monitor. Attach evidence automatically. Socket events must be authenticated, sanitized, persisted before emission, replayable and work across API/worker processes. No simulated live progress.
- Use isolated `mygovguide_phase2_test_*` databases for tests. Run `npm test`, `npm run test:integration`, `npm run build` and relevant `node frontend/scripts/e2e.mjs` suites. Explicitly override test URI/database selection and disable live collection/real providers in automated fixture runs.
- Report actual real-content acceptance separately from synthetic edge tests: scheme-to-rules-to-form, notices, language/voice/manual controls, source execution, old-database hashes and precise blockers. Do not declare the project complete from fixture or architecture tests alone.
- Continue ordinary authorized edits/testing without routine approval questions. External rights, paid spending and genuine editorial decisions cannot be invented. Stop owned temporary services after verification; never terminate another developer's terminal or OpenCode session.
